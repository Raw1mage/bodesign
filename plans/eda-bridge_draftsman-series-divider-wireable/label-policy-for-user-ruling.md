## 3. 作廢節：本文件 2026-09-07 之前的兩個錯誤

**兩則都不是「量錯」。兩則的探針都跑得很正常、都配了控制組、控制組都通過。**

### 3.1 `170`（上限列）：那條政策在樹裡有**兩份實作**

```
composer.py:2227      compose 階段算出 label_nets，當 kwarg 傳給 emitter
kicad_emit.py:1274    emitter 收到 label_nets 之後，又自己呼叫
                      capacity_plan.decide_route_policy 重算一次 cross-IC，
                      結果 OR 回 label_nets（:1282）
```

- **round 26 的探針同時攔了兩處** → 該 commit 上得 170（今日 HEAD 重跑為 **180**）
- **round 29 的探針只 patch 了 composer 那三條規則** → emitter 的重算原封不動，
  把 8 條 cross-IC net 又加回 label → **124**

**兩個數字都對，它們回答的是兩個不同的問題。**

> **新判準（本次事故產出，已蒸進中央 KB）**：
> **要「關掉某條規則」之前，先數這條規則在樹裡有幾個實作點。**
> **`pass-through 控制組只證明 wrapper 沒有污染讀數，證明不了 wrapper 涵蓋了全部作用點。`**
> 一個只攔一半的 wrapper，pass-through 時同樣完美複現 baseline。
> 這條線用了 30 輪的那個標準控制組，**在這一類缺陷上結構性無效**。

機制層歸因：`kicad_emit.py:1270-1274` 的註解逐字寫著
`this decision's SINGLE SOURCE OF TRUTH is now the L2.5 capacity layer`——
**它宣告自己是唯一真相來源，而 compose 端仍保留一份等價推導，兩份都在跑。
那句「已經去重了」的註解本身就是這格的誘因。**

### 3.2 `all_label=True → 64/0`：**結論碰巧正確，而支撐它的那一格是空的**

產生本表的 `policy_table.py`，最後一行逐字是：

```python
run("all_label(lower)", drop=None)   # real all_label below
```

`drop=None` ＝ **pass-through**。它的 log 也確實印著 `wire=116 junction=6`，
**與 baseline 逐字相同**——而表上寫的是 `64 / 0`。那 64 是從別處帶進表裡的，
不是這支探針量的。

今日實測真正的 `all_label=True`：**`wire=64 junction=0 有線 net=0
global_label 43→75`**。**數字是對的。**

**這一類比「結論錯」更難抓**：結論正確，所以沒有任何東西會不一致，
不會有人去比對「表上的數字」與「探針 log 印出的數字」。
**偵測方式只有一個：逐列比對表與 log，而不是只檢查表自身是否自洽。**

## 4. 哪些結論**存活**

上面兩則作廢只動到絕對數字。**三個定性結論在重測後全部成立**，
它們是本表唯一還站得住的部分：

1. **「只拿掉 high-fanout」完全沒有變化**（120/6 → 120/6）。因為 `SYS` 與 `BATT`
   **同時也是 cross-IC**，拿掉一個理由另一個還在。**三條政策的作用面重疊，不能相加。**
2. **上限只到真板的 42%**（180 vs 426；原表寫 40%，重測後為 42%）。
   **所以 426 這個數字不可能單靠改政策達成。**
3. **拿掉政策的代價是急遽上升的碰撞**：reserve 拒絕從 5 暴增到 **50**、
   anti-fusion 從 2 到 10（原表為 3→45）。那正是 `M6-8d` 當初要解決的東西——
   **政策不是憑空加的，它換掉的是一團打結的圖。**

## 5. 這張表為什麼不再是決策依據

**兩格後續量測把它的前提整個換掉了。**

### 5.1 「差 227 條線」不是缺口（round 29 ③-b）

判準在量測之前宣告，偏差方向也是：**K 支腳要表達成同一個節點，最少需要 K−1 條邊；
正交走線每條邊最多 2 段。** 所以「連接原理」是下界、「畫法」是上界，真值被夾在中間。

```
真板 426 段裡，「連接原理」含量介於  105 ~ 210 段
我們現況                              124 段   ← 已落在區間內
```

`GND` 一條就佔 144 段、**每支腳 2.94 段**——那是人手畫圖的風格總量，不是連接原理。
**追上 426 不是目標，而且可能永遠不該是目標。**

### 5.2 真板的形狀是「切開各畫各的」，不是「畫更多線」（round 28-29）

```
真板：root + 3 張葉 sheet，依功能子系統切（POWER / MCU / IO）
      hierarchical_label = 0
      local label        = 0
      global_label       = 18   ← 且 18 = Σ(每條 net 跨幾張紙)，可推導不是巧合
我們：.kicad_sch 產生點 = 1，page "1" 是寫死字面值
```

**人手對 cross-IC bus 的解法不是「別畫」也不是「畫成一團交叉」，是「切開，各畫各的」。**
而我們的產出形狀缺「分頁」這個維度——所以 `M6-8d` 當初面對的
「12+ 條無序交叉」是**單張紙逼出來的**，不是 bus 本身的性質。

⚠ **一句必須帶著走的限制**：真板那 426/56 是**人手繪製**的。其中多少屬於「風格」、
多少屬於「缺陷」，**幾何統計分辨不出來**。那不是量測做得不夠細，是這個量測方法的
射程邊界——**要分辨得問畫圖的人。**
