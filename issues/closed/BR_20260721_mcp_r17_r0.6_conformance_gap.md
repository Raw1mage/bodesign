## 真正缺口（實作目標）

### 1. R17.1.1 / R17.1.2 — `bodesign_init` 缺 machine-readable capability summary

- 現況：`server.py:1409-1410` 只回 `{"ok", "doctrine": <markdown>, "source"}` — **純 prose**。
- 缺：結構化 `capabilities` 物件（`transport` / `file_ingress` / `file_egress` / `webdav_state` / `companion_skill` / `conditional_tool_families`）。
- 缺：service/container endpoint vs host-visible endpoint 的**機器可辨旗標**；目前 `unix://…/bodesign.sock:/mcp/` 混在 `mcp.json:7` 與 landing HTML `install_register`（`server.py:1509`）的可複製註冊字串中，無旗標標記其為**非 host-executable**。
- R17.1.2：需有 conformance test 可分支的結構化 payload（非只驗 text 存在）。

### 2. R17.2.2 — 缺 portable MCP `resources/read` egress

- 現況：**完全無** `@server.list_resources()` / `@server.read_resource()`（grep 僅命中 WebDAV `_dav` 內部 locals `:2121-2128`，無關）。
- egress 只有 HTTP blob route；缺 portable MCP resource 檢索路徑（R0.1 floor 要求 bare client 走 `resources/read`）。

### 3. R17.2.3 — 缺 token workspace 檢視（list/status/probe）

- 現況：`run_tool` 只在 call **之後**算 `produced`（`server.py:1451`），無 transform **前**列 token tree 的工具。
- 域內 preflight（`placement_preflight:1003`、`autoroute_preflight:1000`）是電性 DRC，非「預期資產是否存在於 workspace」。
- 缺：列舉 token namespace tree 的 list/status 工具。

### 4. R17.2.4 — 缺 typed asset preflight（render/assemble/emit 前）

- 現況：`safe_join` / `target.relative_to(root)`（`:2347-2348`、`:2393-2397`）是 I/O 時防逃逸，非 mutation 前的 typed 資產解析閘。
- `emit_fab`（`_h_fab:190`、tool `:1045`）/ `render_board_model`（`:281`/`:1095`）/ `emit_doc` / `compose_schematic` 皆**不**在 render 前拒絕 unresolved paths / missing media / host-only 絕對路徑。
- 缺：R17.2.4 preflight primitive + R0.5 remedy 行。

### 5. R17.2.5 — 缺 content-assertion 契約

- 現況：grep `expected_files`/`expected_media`/`expected_pages`/`required_text`/`non_empty`/`assert_` **零命中**。
- `emit_fab`/`emit_doc`/`render_*` 回 produced-file 清單但不 assert non-empty/expected-count；transport-valid-but-EMPTY 成品未被標為 NOT delivery-ready。
- 最接近的 `compose_schematic` `unresolved_pins`/`warnings`（`:156`）非 content-assertion。
- 缺：assertion 參數（expected counts / required text / non-empty）+ 空成品拒絕。

### 6. R17.6 (a)-(e) — 五個 conformance 情境目前 silent-pass

- (a) host-readable FUSE 檔當未驗證 container path — 無邊界檢查；(b) init 推薦只含 container socket path 的 UDS 指令 — 無機器旗標（繫於 gap 1）；(c) assemble/render 帶 unresolved media 完成 — silent（繫 gap 4）；(d) 空 template 回 `ready=true` — 無防護（繫 gap 5）；(e) skill/guide/manifest 宣告不同 transfer rail — 無 single-source 保證。
- 全部映射到 gap 1–5，隨其修復收斂。

### 7. R0.6 — companion-skill wall-nudge 整條缺

- 現況：**無** `_skill_nudge.py`；grep `nudge`/`wall`/`skipped the contract`/`correct_primitive`/`fingerprint` **零命中**（僅無關 `wall_thickness_mm` 外殼參數）。
- **R0.6.2** 無 toolcall wall-fingerprint detector（bad-shape id / grain-mismatch zero-element edit / 首次無 recon 的 unbounded sweep）。
- **R0.6.3** 無 hard（enrich 既有 failure + `skill(bodesign)`；silent `ok=true` no-op 轉 loud failure）/ advisory（非阻塞 hint，不把 success 轉 failure）兩級。
- **R0.6.4** 無 single-source remedy generator，無 `_render_remedy_line` 把結構化 remedy 投影到 MCP `content` text。
- 可複用的相鄰 fail-loud pattern（供 build 起點）：`TOOL_LANDED` enrichment `:1388-1396`、`KB_UNAVAILABLE`+`_KB_REMEDY` `:804`/`:819-830`、`run_tool` error wrapper `:1446-1447`。
- reference 校準：`/home/pkcs12/projects/docxmcp/bin/_skill_nudge.py`（單一 `skill_nudge_note`/`_remedy`/`_advisory` generator + 3 intercept points + server 端 `_render_remedy_line`）。
